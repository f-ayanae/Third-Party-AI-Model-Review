# Third-Party Model Review

*Public-evidence readiness review of a credit bureau score*

**What this is.** A case study. A fictional German direct bank, Mainkai Direktbank AG, is deciding whether to adopt a real German credit bureau's new 12-criterion score as its primary bureau score for unsecured instalment loans. The repo holds the review, the evidence register, a calculator built from the published points table, an outcomes-test harness, and the decision memo.

**What it is not.** It is not an audit, a validation, a certification, an assurance opinion or legal advice. The work uses public sources only, and the author had no access to the bureau's data, code or contracts. Calculator results describe the published table, not how the bureau scores real people. The bureau is anonymised in this public version.

**Who it is for.** Model risk and third-party risk teams first, AI governance second.

**Result:** *defer pending evidence* (outcome rule 3). Under the ratability test, outcomes analysis (element H) is the only core element with no visible result on the public record. The findings are 0 Critical, 9 High, 4 Medium and 1 Low; the scenario test shows the same rules give *approve with conditions* once a retro-score passes the champion-challenger test, and *reject* if criterion 4 stays and counsel calls it address data. The most time-critical item is F01: from 20 November 2026, §37a(2) No. 1(d) BDSG excludes address data from scores, and criterion 4 is "age of current address". Figures from the Bondora proxy run are in section 3 of the review; they are computed from the data at build time, not typed in.

## Rebuild

With `make` (Linux, macOS, Git Bash):

```bash
pip install -r requirements.lock && playwright install chromium   # Python 3.14, see .python-version
make all          # lab -> register -> tests -> render -> review, memo and crosswalk PDFs -> calculator -> lint
make fixture      # self-test of the outcomes harness on the synthetic fixture
make named        # private named version (needs the private/ overlay; never publish)
```

Without `make` (Windows PowerShell, from this folder):

```powershell
python lab/run_lab.py
python evidence/build_register.py
python -m pytest -q
cd src; python -m assurance.render; cd ..
python tools/to_pdf.py deliverables/review.html deliverables/Third_Party_Model_Review.pdf
python tools/build_pdfs.py
python tools/build_calculator.py
python tools/prose_lint.py
```

Bondora proxy run (investor export; see docs/DECISIONS.md D6, D13 to D16 and D29):

```bash
python lab/bondora/download.py --file ~/Downloads/loan_dataset_investor.xlsx   # converts and hashes
make bondora CSV=data/bondora/loan_dataset_investor.parquet                     # tests + charts
```

Only aggregates covering at least 30 loans are written. Raw rows are never committed (see docs/LICENCES.md).

## What this does not prove

Latency, availability, access control, secrets management, model change management, incident response, log retention and data residency. Section 11 of the review lists, for each one, the evidence a real lender or bureau would hold.
